자문 + spike 두 정보원 일치로 confidence ~99%.

### D15 — `last_settled_funding_time` 역산 매핑
- premiumIndex 응답에 직접 필드 없음 (WebFetch 1 확정)
- `time` 필드 = 현재 서버 시각 (NOT 정산 시각)
- 정공: `nextFundingTime - fundingIntervalHours × 3600 × 1000`
- 적용: `normalizeUsdmPremium(raw, fundingIntervalHours: number = 8)` 시그니처 확장

### D16 — `annualizedBasisRate` 응답 그대로 저장, 카드 노출 X
- WebFetch 2 결과 PERPETUAL 환경 `annualizedBasisRate = ""` 빈 문자열 (Binance 의도적 비움)
- 잠정 가설 `basisRate × 8760` = -525% 같은 무의미 값 검증
- 정공: `num()` 헬퍼가 `""` → null 자동 변환, DB 저장만 (deferred `[8-2]` 옵션 B 확정)

### D17 — perSymbolTask 단일 task 6 fetcher 직선 + rate-limited dispatcher
- 옵션 B (병렬 2 task) 는 같은 IP bucket 공유 → 실질 병렬 이득 0
- 옵션 A (단일 task) + `X-MBX-USED-WEIGHT-1M` 80% backoff
- cycle ~12분 수용 (LSR/basis 분 단위 stale 허용)
- 적용: Sub-substep C 영역

### D18 — `premiumIndexTask` 30분 고정 polling
- `last_settled_funding_rate` 정산 직후 4h/8h 고정 (oversampling 8~16배 충분)
- weight 10, 분당 quota 6000 의 0.005% 사용
- 적용: `premiumIndexTask.ts` 신설 완료

### D19 — basis per-symbol (`pair` 파라미터 필수), period=1h 고정

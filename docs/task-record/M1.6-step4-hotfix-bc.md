## 📖 비전공자 친화 — 무슨 일이 일어났나

Step 4 commit (`f081aaf`) 로 schema/registry 정공 작업 완료한 직후, 사용자가 카드 갱신을 검증하다 **두 가지 사고** 발견:

### 사고 1 — 카드 갱신 안 됨 (DB 40h stale)
**원인 비유**: M1.6 Step 3.5 에서 "큰 우편함 (full ticker 17 필드)" 으로 바꿨는데, 사용자 Windows 컴퓨터의 우체통 (ws 라이브러리) 이 큰 우편함을 처리 못해 **메시지 0건 받기** + **150초 후 강제 재연결** 무한 cycle. 사용자 컴퓨터 끄고 다시 켰더니 그 후 약 40시간 동안 worker 가 데이터 적재 못 함.

**해결**:
- **Hotfix C** (`perMessageDeflate=false`): ws 라이브러리 압축 해제로 큰 페이로드 stall 회피 시도. Windows + ws + 큰 payload 콤보의 알려진 문제 (ws#1810).
- **Hotfix B** (`!ticker@arr` → `!miniTicker@arr` 임시 롤백): 페이로드 17필드 → 6필드로 ~3배 감소. 빠진 11필드 (특히 24h 변화율) 는 1분 주기 REST 폴링 (`ticker24hrBatchTask`) 으로 보강.
- **결과**: SPOT/COINM 정상화 (1초 sync), USDM 만 여전히 환경 특수 사고 (`fstream.binance.com` selective stuck) → REST 1분 batch 의존으로 1분 stale 까지 보강.

### 사고 2 — 24h Volume Leaders 카드에 BTCIDR/BTCJPY 등 fiat 페어 1위
**원인 비유**: 마트 진열대에 한국 상품은 원화(₩), 일본 상품은 엔(¥), 인도네시아 상품은 루피아(Rp) 가격표 — "숫자가 큰 순서로 정렬" 하면 인도네시아 상품이 무조건 1등 (1 USDT ≈ 16,000 IDR 이니까). BTCIDR raw quote_volume = 4.3B IDR ≈ 250K USDT 환산 (BTCUSDT 491M USDT 의 1/2000) 인데 raw 정렬에서 위로.

또한 **Binance API 비대칭** 발견: 글로벌 API `/api/v3/exchangeInfo` 가 regional 페어 (Binance Indonesia/Japan/TR 운영) 도 같이 push → 우리 워커가 의심 없이 받아 적재. 그런데 사용자가 보는 글로벌 `binance.com/en/markets/spot` 사이트에는 fiat 페어 노출 안 됨. **사이트=DB 일치 원칙 위반**.

**해결 (B1 즉시)**:
- `now_spot_ticker` description 에 "Default scope: USDT/USDC/FDUSD/BTC/ETH/BNB quote 만 default" 명시
- `buildSystemPrompt` 본문에 같은 가이드 1단락 추가
- AI 가 자연어 의도 추론으로 default filter 적용 (CLAUDE.md "AI 의도 추론 공간 좁히지 말라" 정합)

**정공은 deferred**:
- `[3-54]` `quote_volume_usd` 컬럼 + worker USDT 환산 (M1.7 Step 7 또는 M2)

## 0. 한 줄 요약 (비전공자용)

**"AI 에게 말 거는 전화기 + 통화 대본"** 을 만들었습니다.

전화기(`haikuClient`)는 Anthropic 의 Claude Haiku 4.5 에게 실제로 전화를 거는 최소 래퍼 — "API key 꺼내서 질문 보내고 답 받기" 만 담당합니다. 재시도 / 검증 / 토스트는 Step 2~4 의 일이라 여기서는 건드리지 않습니다.

대본(`buildSystemPrompt`)은 AI 에게 건네는 매뉴얼 — "너는 TRAVIS 오케스트레이터야, 외부 API 직접 호출 금지, 이런 재료(4개 레지스트리: 거래소·데이터소스·컴포넌트·인터랙션)가 있고, 답은 이 JSON 모양으로" 를 XML 태그로 정리해 Haiku 에게 건넵니다.

실제 Haiku 4.5 에게 "한 단어로 `ready` 라고만 답해" 요청 → `"ready"` 응답 수신 확인 (input 3,181 tokens / output 4 tokens / ~$0.0033). 전화선 살아있음 확증.

## 1. 신규/수정 파일 (6건)

### 1-A. `apps/web/lib/ai/haikuClient.ts` (신규, 202줄)

**역할**: Anthropic SDK 0.90.0 의 `messages.create` 를 TRAVIS 전용 최소 래퍼로 감싼다.

**핵심 설계**:
- **모델 상수 3개**: `HAIKU_MODEL_ID = "claude-haiku-4-5-20251001"`, `SONNET_MODEL_ID = "claude-sonnet-4-6"`, `ESCALATE_TO_SONNET_FLAG = false as const`
- **에러 3종 (name readonly override)** — Step 2 fallback 이 `err.name` 으로 분기:
  - `MissingAnthropicKeyError` — env 누락
  - `AnthropicTransportError` — 네트워크/5xx (native `Error.cause` 활용)
  - `AnthropicInvalidResponseError` — content 블록 비정상 (`.raw` 로 원본 접근)
- **Lazy singleton `getClient()`** — 모듈 로드 시점이 아닌 최초 호출 시에만 env 검증 + SDK 인스턴스 생성 → 빌드/테스트 환경 crash 회피
- **`extractContent()` 헬퍼** — text/tool_use 블록 분리 추출. Step 2 `tool_choice` 전환 시 같은 헬퍼로 `tool_use.input` 꺼내기 가능
- **3중 Server-only 방어선** (상단 주석 명문화):
  1. `process.env.ANTHROPIC_API_KEY` 에 `NEXT_PUBLIC_` 접두사 없음 → Next.js 자동 제거
  2. 호출 그래프 규율 — `app/api/orchestrate/route.ts` 등 서버 전용에서만 import
  3. `typeof window !== "undefined"` 런타임 가드 — 실수 방지
- **DEFAULT_TEMPERATURE = 0.2** — JSON 안정성 확보 (사용자 결정 2026-04-22)
- **DEFAULT_MAX_TOKENS = 4096** — 카드 10개 + notes 200자 + 헤더 커버

**Public API**: `callHaiku({ system, user, maxTokens?, signal? }): Promise<CallHaikuResult>`

**반환 shape**: `{ text, toolUses, stopReason, usage: { inputTokens, outputTokens, cacheReadInputTokens?, cacheCreationInputTokens? }, raw }`

### 1-B. `apps/web/lib/ai/buildSystemPrompt.ts` (신규, 134줄)

**역할**: 4개 레지스트리 + 역할/가드레일/출력 포맷 가이드를 XML 섹션으로 합성.

**섹션 구조**:
```
<role>...</role>
<guardrails>...</guardrails>
<registries>
  ## Available Exchanges
  ## Available Data Sources
  ## Available Components
  ## Available Interactions
</registries>
<output_format>
  규칙 bullet 8개 + 예시 2개 (updateMode "value" / "content")
</output_format>
```

**설계 결정 (사용자 승인)**:
- XML 태그 구분 — Anthropic 공식 권장, Haiku 구조 준수율 ↑
- **JSON Schema 전체 serialize 는 미도입** — Step 2 에서 `tool_use input_schema` 로 Anthropic 레벨 강제 검증이 붙으므로 프롬프트의 스키마 설명은 중복/혼동 유발
- 예시 2개는 완료 기준 10개 중 주요 2 모드(value/content)를 정확히 조준
- `locale` 파라미터는 M2+ 다국어 확장 여지만 남기고 현재 `void options;` no-op

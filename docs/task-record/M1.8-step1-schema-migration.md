## 1. 배경 — 왜 본 작업인가

M1.8 §8.0 자문 결과 (`@crypto-domain-expert` 11 의제 + WebFetch spike 3건, 2026-05-24) 가 결정적 사실 입증:

1. **Predicted vs Realized funding rate 별개 metric** (D8) — `markPriceUpdate.r` (WS) = predicted next funding (1초 변동) / `premiumIndex.lastFundingRate` (REST) = realized last settled (정산 직후 고정).
2. **`fundingInfo` endpoint 존재** (D9) — `/fapi/v1/fundingInfo` 가 4h/8h funding interval per-symbol 식별. PHAROSUSDT 4h 실측 입증.
3. **Basis 컬럼 부재** — `now_futures_indicator` 에 basis / basis_rate / annualized_basis_rate 미존재.
4. **`last_settled_funding_time` 정확한 매핑 = 역산** (D15) — premiumIndex 응답에 직접 필드 없음, `nextFundingTime - fundingIntervalHours × 3600 × 1000` 역산이 유일한 정공.

→ Schema migration 4 ALTER 필요 (사용자 D1~D14 묶음 승인 + WebFetch spike 후 D15~D19 추가 묶음 승인).

## 2. Migration SQL (Supabase Studio SQL Editor 적용, 옵션 B)

`mcp__supabase__apply_migration` 가 read-only mode 거부 → 사용자가 Supabase Studio SQL Editor 에 직접 붙여넣어 실행 (옵션 B, 가장 안전).

```sql
-- M1.8 §8.1 — Schema migration: funding predicted/realized 분리 + basis ADD + funding_interval_hours
-- 청사진: docs/task-record/M1.8-step0-pre-infra.md §5
-- 사용자 결정 D8 / D9 (2026-05-24 묶음 승인)

-- now_futures_indicator: funding 컬럼 분리 + basis 3종 신설
ALTER TABLE now_futures_indicator
  RENAME COLUMN last_funding_rate TO predicted_funding_rate;

ALTER TABLE now_futures_indicator
  ADD COLUMN last_settled_funding_rate NUMERIC,
  ADD COLUMN last_settled_funding_time BIGINT,
  ADD COLUMN basis NUMERIC,
  ADD COLUMN basis_rate NUMERIC,
  ADD COLUMN annualized_basis_rate NUMERIC;

COMMENT ON COLUMN now_futures_indicator.predicted_funding_rate IS
  'Predicted next funding rate (raw decimal, e.g. 0.0001 = 0.01%). Source: WS !markPrice@arr@1s `r` field, 1초 변동. Binance 사이트 우상단 funding(4h)/Countdown 박스의 큰 숫자. 카드 표시 시 *100 후 % 부착 + interval 라벨.';

COMMENT ON COLUMN now_futures_indicator.last_settled_funding_rate IS
  'Realized last settled funding rate (raw decimal). Source: REST /fapi/v1/premiumIndex.lastFundingRate (docs verbatim "Latest funding rate"). 정산 직후 4h(또는 8h) 동안 고정.';

COMMENT ON COLUMN now_futures_indicator.last_settled_funding_time IS
  'Last settled funding time (epoch ms). Paired with last_settled_funding_rate.';

COMMENT ON COLUMN now_futures_indicator.basis IS
  'futuresPrice - indexPrice (USD 절대값). Source: REST /futures/data/basis?contractType=PERPETUAL. 9 interval 시계열 지원.';

COMMENT ON COLUMN now_futures_indicator.basis_rate IS
  'basis / indexPrice (decimal, e.g. 0.0002 = 0.02%). 카드 표시 시 *100 후 % 부착.';

COMMENT ON COLUMN now_futures_indicator.annualized_basis_rate IS
  'Annualized basis rate (decimal). PERPETUAL 환경 정의는 Binance docs 침묵 — deferred [8-2] M1.8 §8.5 사이트 비교 후 노출 결정.';

-- symbols 마스터: funding_interval_hours 신설 (D9 — instrument 속성)
ALTER TABLE symbols
  ADD COLUMN funding_interval_hours SMALLINT;

COMMENT ON COLUMN symbols.funding_interval_hours IS
  'Binance /fapi/v1/fundingInfo.fundingIntervalHours (4 or 8). NULL = SPOT 또는 fundingInfo 응답 미등재 = default 8h fallback (negative-space 정의). 24h reload 주기. PHAROSUSDT 같은 4h funding 코인 식별 source.';

-- history_futures_indicator: now_* 동일 정합
ALTER TABLE history_futures_indicator
  RENAME COLUMN last_funding_rate TO predicted_funding_rate;

ALTER TABLE history_futures_indicator
  ADD COLUMN last_settled_funding_rate NUMERIC,
  ADD COLUMN basis NUMERIC,
  ADD COLUMN basis_rate NUMERIC,
  ADD COLUMN annualized_basis_rate NUMERIC;

COMMENT ON COLUMN history_futures_indicator.predicted_funding_rate IS
  'Predicted next funding rate snapshot at recorded_at. Source: same as now_futures_indicator.predicted_funding_rate.';

COMMENT ON COLUMN history_futures_indicator.last_settled_funding_rate IS
  'Realized funding rate at last settlement before recorded_at.';

COMMENT ON COLUMN history_futures_indicator.basis IS
  'futuresPrice - indexPrice snapshot at recorded_at.';

COMMENT ON COLUMN history_futures_indicator.basis_rate IS
  'basis / indexPrice snapshot at recorded_at.';

COMMENT ON COLUMN history_futures_indicator.annualized_basis_rate IS
  'Annualized basis rate snapshot. PERPETUAL 환경 정의 검증 후 노출 (deferred [8-2]).';
```

### 사용자 SQL Editor 적용 결과 (2026-05-25)

> "Success. No rows returned" — 4 ALTER + 11 COMMENT 정상 적용.

## 3. 검증 (Supabase MCP `execute_sql` + `list_tables verbose=true`, 2026-05-25)

### 3.1 컬럼 메타데이터 + COMMENT 등록 확인 (12 컬럼)

```sql
SELECT
  c.table_name,
  c.column_name,
  c.data_type,
  c.is_nullable,
  pg_catalog.col_description(format('%I.%I', c.table_schema, c.table_name)::regclass::oid, c.ordinal_position) AS comment
FROM information_schema.columns c
WHERE c.table_schema = 'public'
  AND (
    (c.table_name = 'now_futures_indicator' AND c.column_name IN ('predicted_funding_rate','last_settled_funding_rate','last_settled_funding_time','basis','basis_rate','annualized_basis_rate'))
    OR (c.table_name = 'symbols' AND c.column_name = 'funding_interval_hours')
    OR (c.table_name = 'history_futures_indicator' AND c.column_name IN ('predicted_funding_rate','last_settled_funding_rate','basis','basis_rate','annualized_basis_rate'))
  )
ORDER BY c.table_name, c.column_name;
```

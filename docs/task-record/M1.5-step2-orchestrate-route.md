## 3. 의도적 이월 결정 (2026-04-22)

### 3-A. 부분 성공 허용 → **M2+ 이월**

**정의**: "10 장 카드 중 1 장만 invalid 시, valid 9 장은 즉시 렌더 + invalid 1 장만 AI 에 재요청" 하는 최적화.

**현재 Step 2 방식 (대체)**: 1 장이라도 invalid 면 전체 재시도. 2 회 실패 시 fallback.

**이월 이유 4가지**:
1. **Step 2 scope 이미 큼** — API Route + Zod + 재시도 + 로그 + fallback + service_role client 를 한 번에 엮음. 부분 성공까지 넣으면 "한 번에 하나의 작업" 원칙 위반.
2. **실측 데이터 없음 → premature optimization** — Haiku 4.5 의 JSON 준수력상 "10 장 중 1 장만 틀리는" 패턴 자체가 드묾. 실사용 데이터 없이 선제 구현은 YAGNI 위반.
3. **테스트 가능성 ↓** — 부분 실패 재현이 deterministic 하지 않아 flaky test 위험.
4. **가역성 (역방향 추가 난이도 낮음)** — 부분 성공은 전체 재시도 루프 내부에 분기만 추가하면 됨. 반대로 지금 도입 후 제거는 더 어려움.

**도입 트리거**: M1.5 완료 후 실사용에서 "N 장 중 K 장 invalid" 패턴이 관찰되고, 재시도 1회 성공률이 60% 미만일 때. 구체 메트릭은 `log_validation_failure` 의 `error_message` 필드에서 path 추출로 M1.6 이후 분석 가능.

### 3-B. `log_validation_failure` 컬럼 확장 → **M1.6 이월**

**현재 스키마 (기존 5 컬럼, M1.3 Step 1 에서 정의)**:
```sql
CREATE TABLE log_validation_failure (
  id            BIGINT IDENTITY PRIMARY KEY,
  query_text    TEXT,
  ai_response   JSONB,
  error_type    VARCHAR(50),
  error_message TEXT,
  created_at    TIMESTAMPTZ DEFAULT NOW()
);
-- RLS: 의도적으로 policy 0개 (deny-all). service_role 만 INSERT 가능.
```

**M1.6 이월 예정 컬럼 (ROADMAP M1.6 산출물 섹션에 확정 기록됨)**:
- `user_id UUID REFERENCES auth.users(id) NOT NULL` — auth 연동
- `attempt_number INT NOT NULL DEFAULT 1` — 1차/2차 실패 구분
- `model_id VARCHAR(50)` — haiku/sonnet 별 실패율 추적
- `system_prompt_version VARCHAR(40)` — git commit SHA (프롬프트 버전별 교정율)
- `user_query_hash VARCHAR(64)` — sha256, PII 격리 + 동일 쿼리 클러스터링

**이월 이유 4가지**:
1. **M1.5 는 dev 1명 규모** — 세밀한 분석 도구가 필요한 규모 아님. 기존 5 컬럼으로 "query_text + ai_response + error_message" 를 통해 수동 디버깅 충분.
2. **어차피 M1.6 에서 user_id migration 필요** — auth 도입 시 필수이므로 그 시점에 **한 번의 ALTER 로 일괄 확장** 이 비용 효율적.
3. **기존 `SupabaseDataService.insertValidationFailureLog()` 가 5 컬럼 spec** — 지금 확장하면 worker/web 양쪽 호출 경로 영향. M1.6 에 worker 와 web 동시 업데이트가 자연스러움.
4. **`error_message` 에 임시 저장 가능** — 필요한 메타정보(`attempt=2, model=haiku-4-5-20251001, commit=57abf9d`)를 error_message prefix 로 기록해 Step 2 디버깅 공백 없음.

**M1.5 Step 2 에서 error_message 작성 규약**:
```
[attempt=N, model=<model_id>, commit=<sha>]
<Zod error bullets joined by "\n">
```
M1.6 migration 시 이 규약의 메타를 파싱해 새 컬럼으로 backfill 가능 (또는 과거 row 는 NULL 허용).

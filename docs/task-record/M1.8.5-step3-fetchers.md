## 3. 핵심 설계 결정

### 3.1 recorded_at 폐기 규약 (code-reviewer C1 → 타입 강제)

`recorded_at` 은 자연 키 5축의 한 축이고 DB 는 NOT NULL + DEFAULT now(). timestamp 가 누락/이상이면 undefined 로 흘러 now() 가 박혀 **시계열 오염**. → timestamp ≤ 0 또는 누락 시 **row 전체 폐기 (null 반환)**, 6 함수 전부 동일 규약.

**C1 반영**: generated Insert 타입의 `recorded_at?` 이 optional 이라 가드를 빠뜨려도 컴파일 통과 → 미래 7번째 함수 위험. normalize 반환 타입을 `type HistoryRow = HistoryFuturesIndicatorInsert & { recorded_at: string }` 로 좁혀 **컴파일러가 규약 강제**. fetcher `notNull` 제네릭 type-guard 로 narrow 보존.

### 3.2 ON CONFLICT 자연 키 머지 (D-Q3)

`upsert(rows, { onConflict: "exchange,market_type,symbol,interval,recorded_at", defaultToNull: false })`. 6 metric 이 동일 (symbol, interval, recorded_at) 에 각 endpoint 에서 따로 들어와도 한 row 에 누적 머지. live smoke 확인: 6 endpoint timestamp 가 전부 5m 그리드(300000ms 배수)에 정렬 → 과거 봉은 일치 → 머지 작동.

**mixed-batch 금지 불변** (W1 반영): 호출자(Step 4)는 metric 별 배치 분리 호출 필수. SDK 의 Object.keys union → 누락 컬럼 DEFAULT(NULL) 덮어쓰기 hazard 주석 보강.

**`[8-11]` NOT NULL 함정 검증 — 안전 확인**: `[8-11]` 은 `.upsert(defaultToNull:false)` 에서 INSERT 절의 NOT NULL 컬럼 누락 시 ON CONFLICT UPDATE 발동 전에 INSERT 실패하는 함정. `history_futures_indicator` 의 NOT NULL 컬럼은 자연 키 5축(exchange/market_type/symbol/interval/recorded_at) 뿐이고, **모든 metric 배치 row 가 5축을 항상 포함**(HistoryRow 타입이 recorded_at 까지 강제) → 함정 미발동. fundingInfoTask 사고(NOT NULL 컬럼 누락 partial)와 구조 다름. metric 컬럼(open_interest/basis/...)은 전부 nullable.

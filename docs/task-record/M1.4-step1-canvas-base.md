## 📖 비전공자 친화 설명

이번 Step 1은 **"빈 도화지를 까는 단계"** 입니다. TRAVIS 캔버스 위에는 곧 가격 티커, 코인 리스트, 차트 카드가 올라가는데, 그 전에 **카드를 배치할 수 있는 무한 2D 도화지(React Flow)** 가 있어야 합니다.

도화지에는 카드 1개도 없습니다. 대신:
1. **검은 배경**(#0a0a0b — 유저가 공유한 UI 레퍼런스의 `Command Deck v4` 톤) 에
2. **은은한 점 그리드**(18px 간격, 카드 정렬용 기준점)가 깔려있고
3. **좌하단 3버튼 Control**(+ 줌인, − 줌아웃, 핏뷰)이 있어서
4. **마우스 휠로 줌, 빈 공간 드래그로 팬**이 됩니다.

이게 "보기엔 아무것도 없는데 실제로는 매우 중요한 기반" 입니다. Step 2~5 카드들이 전부 이 도화지 위에 놓이기 때문.

### 비유로 이해하기
- React Flow = **지도 앱**. 지도 위에 핀을 꽂듯 카드를 배치하고, 드래그로 옮기고, 확대/축소할 수 있습니다.
- Zustand = **공책**. 카드들이 어디에 있는지(nodes), 줌/팬이 어디에 있는지(viewport)를 기록하는 공책. 새로고침 시 공책이 지워집니다(세션만 유지). M1.6 로그인 도입 시 Supabase에 저장으로 승격.
- Provider 패턴 = **공책 주인을 명확히**. Next.js 서버가 여러 사용자 요청을 처리할 때 공책이 섞이지 않게, 요청마다 본인 공책만 쓰도록 분리.

## 🧭 주요 의사결정 (2건)

### 결정 #1 — Zustand Provider 패턴으로 승격
**배경**: 기존 `apps/web/lib/store.ts` 는 module-level `create()` 로 작성되어 있고 파일 상단 주석에 "M1.4 에서 Provider 패턴으로 리팩터할 것" 이 명시돼 있음. Step 2 에서 consumer 가 4~5 개로 늘어나면 리팩터 비용이 증가.

**결정**: Step 1 에서 즉시 승격. `createStore` (vanilla) + `createContext` + `useState` lazy initializer + `useStore(ctx, selector)` 훅 패턴.

**왜 `useRef` 가 아닌 `useState` 인가**:
- Zustand 공식 Next.js 가이드의 `useRef(null)` + null 체크 패턴은 **React 18 기준**. React 19 신규 룰 `react-hooks/refs` 가 render 중 `ref.current` 접근을 금지.
- `useState(() => createStore())` lazy initializer 는 최초 1회만 호출되고 render 중 ref 접근이 없어 React 19 호환.
- Strict Mode 이중 호출은 factory 가 순수(side-effect 없음)하므로 무해 — 두번째 인스턴스는 GC.

### 결정 #2 — `dynamic(ssr:false)` 제거 후 정적 import
**배경**: 최초 구현은 `dynamic(() => import(...), { ssr: false, loading: () => ... })` 로 React Flow 를 로드. Next.js 16 에서 즉시 빌드 에러 — **"ssr: false is not allowed with next/dynamic in Server Components"**.

**결정**: `dynamic()` 완전 제거. `CanvasWorkspace` 자체가 `"use client"` 를 가지고 있으므로 Server Component 에서 정적 import 해도 Next.js 가 자동으로 client boundary 생성. React Flow 의 `useLayoutEffect` / DOM 측정은 client hydration 이후 실행되므로 mismatch 없음.

**잃은 것**: 로딩 fallback UI ("TRAVIS · 캔버스 준비 중…") 문구. 초기 렌더 <100ms 라 실사용 체감 없음.

## 📋 도메인 특이사항

### Next.js 16 App Router 규칙
- `dynamic(..., {ssr: false})` 는 **Client Component 에서만** 허용. Server Component 는 정적 import 로 해결.
- `"use client"` 파일을 정적 import 해도 번들 오염 없음 — Next.js 가 자동으로 client chunk 로 분리.

### React 19 신규 린트 룰
- `react-hooks/refs` — render 중 `ref.current` 읽기/쓰기 금지. 초기화는 `useState` lazy initializer 또는 `useEffect` 로.
- Zustand 공식 문서의 `useRef` 패턴을 맹목적으로 따라하면 이 룰에 걸린다.

### Zustand 스토어 분리 규칙 (`nextjs-frontend-specialist.md` §3.1)
- "never one god store" — canvas / chat / view 를 하나로 합치지 않음.
- 현재: `canvasStore` 하나.
- 예정: Step 6 에서 `chatStore`, M1.6 auth 시 `viewStore` 별도 파일 추가.

수정: `"ticker"` → `"ticker-card"`, `"coinList"` → `"coin-list-card"`, `"klineChart"` → `"kline-chart-card"`. `actionDispatcher.test.ts` 의 fixture componentId 도 같이 정합.

### Step 3a (2026-04-22) — dispatcher 확장

**설계 근거**: `packages/shared/src/schemas/orchestrateResponse.ts` L18-19 주석 — "Step 3 교체 시 코드 최소화 목적으로 top-level union 설계". 호출자(ChatInputBar) 가 switch 를 하지 않고 dispatcher 가 단일 진입점에서 분기.

**DispatchFailure reason enum 확장**:
- 기존 `"validation" | "empty" | "store-error"` → `"validation" | "fallback" | "empty" | "store-error"`
- `fallbackReason?: OrchestrateFallbackReason` 필드 추가 — reason === "fallback" 시 `validation_exhausted` / `transient_error` / `upstream_error` / `timeout` 중 하나.

**테스트 업데이트**:
- (a)~(e) 기존 5 케이스: `successEnv()` 헬퍼로 `{kind:"success", payload}` 래핑.
- (f) 신규: fallback 응답 → 토스트 표시 + reason=`"fallback"` + fallbackReason=`"validation_exhausted"` 검증.
- (g) 신규: 최상위 kind 누락 입력 → Zod discriminator 에러로 `"validation"` 실패. **payload-only 옛 시그니처가 실수로 전달돼도 안전하게 거부** 됨을 증명.

**결과**: 7/7 PASS, type-check/lint 0 errors.

}

## 📖 비전공자 친화 설명

**TRAVIS 의 "데이터 배달망 + 행동 기록부" 를 산업표준으로 다시 짜는 단계입니다.**

Step 1 (출입증) + Step 2 (출입대장) 까지는 "신규 인프라 추가" 였지만, Step 3 는 **기존 카드 코드를 리팩터링** 하면서 **잠복 버그 1건을 구조적으로 해소** 하는 단계.

### 비유 — 거래소 내부 우편실 (dataService) + 영수증 묶음 발행기 (sessionFlusher)

#### 1. dataService = "거래소 내부 우편실"
예전엔 각 카드(BTC 가격, 코인 리스트 등)가 각자 우편함을 만들어 직접 우체국(Supabase)에 줄을 섰습니다. **같은 종류 카드 2장을 띄우면 우편함이 충돌해 한 카드는 편지를 못 받는 잠복 버그(`[3-33]`)** 가 있었습니다.

이번에 **datasource(우편물 종류) 별 우편함 1개** 를 우편실(`channelManager`)이 운영하고, 카드는 "이 종류 우편물 들어오면 알려줘" 라고 등록만. N장 카드가 같은 종류를 봐도 우편함은 1개. Supabase 가 부과하는 동시 연결 200개 한도(베타 단계엔 충분하지만 아낄수록 좋음)도 절약.

#### 2. sessionFlusher = "영수증 묶음 발행기"
트레이더가 카드 1장을 30분 동안 10번 드래그·5번 리사이즈 하면 옛 정책은 15장의 영수증(DB row)을 발행 — 베타 10명이면 월 33만 row 폭증. 이제는 **카드별 메모리 카운터에 누적** 했다가 4가지 시점 중 하나에서 1 row 로 압축 발행 — 월 2만2천 row(15배 절감).

**4가지 발행 시점 (사용자 결정 옵션 B-improved)**:
1. 5분 동안 카드 안 만지면 자동 (idle timer)
2. 탭 전환 / 모바일 백그라운드 진입 (visibilitychange)
3. 브라우저 종료 직전 (pagehide + sendBeacon — 산업표준 페이지 종료 직전 비동기 보장)
4. 카드 자체 unmount (보너스)

**결정타 — "안 만진 카드는 영수증 0장"** (idle skip): "보기만 하고 안 만지는 카드" 는 row 0. 사용자가 "주로 보는 카드는 안 지운다 + PRD §156 My Views 도입 후 unmount 거의 없음" 두 도메인 사실 지적의 정공법.

#### 3. 사용자 쿼리 SHA-256 해시 (PII 격리)
admin (M1.7) 이 사용자 query 원문 못 봐도 "동일 질문 군집" 분석 가능. 클라이언트 Web Crypto API 로 64자 hex hash 계산 → server 에 query 와 함께 전송 → log_chat 에 저장.

#### 4. logger factory + boilerplate 통합
M1.6 Step 2 의 logChat / logValidationFailure 가 ~90% 중복 (lazy singleton + try/catch + service_role). Step 3 의 logBehavior 신규 추가 시 3 파일 동일 골격 → factory (`createLogger`) 로 추출. boilerplate 90% 감소 + "로깅 정책 변경 1 곳 전파" 효과.

### Realtime 단일 channel 패턴 — `옵션 Z` 채택 (backend-infra-specialist 자문)

기존 hook 들은 listener 추가마다 channel teardown + rebuild 하는 옵션 X/Y 방향이었는데, 시니어 자문이 "**`.on()` 은 평생 1회만, listener 는 manager 의 dispatch table 에만 등록**" 패턴 (옵션 Z) 제안. Supabase channel quota / 재구독 지연 / race window 3가지 문제가 한 번에 사라짐. `[3-33]` 자연 해소의 진짜 이유.

### React 19 호환 — `useSyncExternalStore` 패턴 (nextjs-frontend-specialist 자문)

channel manager 가 fan-out 시 카드 측 setState 호출하는 패턴이 React 19 의 `react-hooks/set-state-in-effect` 규칙과 **회색 지대**. `useSyncExternalStore` 가 외부 store 의 표준 React 통합 — 자동 batching + tearing 방지 + StrictMode 안전 모두 무료.

## 🧭 주요 의사결정

### 1. **옵션 Z (단일 channel + dispatch table)** — backend-infra-specialist 자문 채택

- **기각된 옵션 X / Y**: listener 추가마다 channel teardown + rebuild. Supabase quota 낭비 + 재구독 ack 왕복 ms 동안 payload drop + race window.
- **채택 옵션 Z**: `.on()` 평생 1회만 호출, listener 추가/제거는 manager 의 dispatch table 만 갱신. channel 자체 손대지 않음.
- **결과**: `[3-33]` 자연 해소 + Free Tier 200 connection 한계 안전 + Strict Mode race 안전.

### 2. **`useSyncExternalStore` 패턴** — nextjs-frontend-specialist 자문 채택

- React 19 `react-hooks/set-state-in-effect` 규칙과 회색지대 회피 + tearing 방지 + StrictMode 안전.
- snapshot 안정성: `snapshotRef.current` 객체를 새 참조로 교체 → React 가 === 비교로 변경 감지.

### 3. **옵션 B-improved (4중 flush 가드 + idle skip)** — 사용자 결정 (2026-04-26)

- 사용자 우려 ("주로 보는 카드는 안 지움 + PRD §156 My Views 도입 후 unmount 거의 없음") 의 정공법 답.
- 4중 trigger: 5min idle / visibilitychange / pagehide+sendBeacon / unmount + idle skip ("dragCount + resizeCount === 0" 카드 row 0).
- 비용: debounce 만 (337K row/월) 대비 **15배 절감** (~22K row/월).

### 4. **`log_behavior.payload` 5KB 상한 (`ensurePayloadSize`)**

- 사용자 결정 (2026-04-26) — DB 폭주 방지 application 가드.
- 초과 시 `{ __truncated: true, originalSize, fieldName }` marker 객체 + console.warn.

### 5. **dataService 위치 = `apps/web/lib/dataService/`** (worker 와 분리)

- 워커 `packages/data-service/` 와 분리 — 프론트 카드 shape 은 워커 task shape 과 다르고, RLS 통과 anon client 사용. 워커 service_role 과 격리.
- M2+ GraphQL / WS 직접 / TimescaleDB 등 다변화 시 본 디렉토리만 교체 가능 (`supabaseAdapter` 어댑터 경계).

### 7. **client-side filter 채택** (server-side filter 미사용)

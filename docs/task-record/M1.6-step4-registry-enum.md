## 📖 비전공자 친화 설명

**TRAVIS 의 "AI 환각 차단 게이트" 를 schema 단계에 신설하고, AI 가 보는 데이터 메뉴를 5배 풍부하게 만든 단계입니다.**

### 비유 — "주방의 재료 검수 직원" + "메뉴판 풍부화"

AI 는 카드 JSON 을 "주문서" 로 만들고, Zod schema 는 "주방 검수 직원" 입니다. 옛 검수 직원은 무사태평했습니다 — `componentId: "screener-card"` 같은 등록되지 않은 이름이 와도 "1글자 이상이면 OK" 만 보고 통과시켰습니다. 통과한 주문서는 주방 안쪽 (React) 에서 silent fail (빈 카드).

이번 Step 4 에서 검수 직원이 깐깐해졌습니다:
- **"등록부에 있는 이름인가?"** 즉시 점검 → 없으면 거부 + **"현재 등록된 카드는 ticker-card / coin-list-card / kline-chart-card 입니다"** 정답 후보까지 알려줌. AI 가 다음 retry 에서 정답을 즉시 인지.
- **"필터 필드가 그 datasource 의 메뉴에 있는가?"** — `now_spot_ticker` 에 `base_asset` 같은 hallucinated 필드를 쓰면 즉시 차단.
- **"실패하면 왜 실패했는지 더 자세히 분류"** — 옛 1종 (`validation_exhausted`) 에서 2종 (`parse_error` / `schema_drift`) 으로 쪼갬. 운영 admin 로그에서 "JSON 자체 깨졌나 vs shape 만 안 맞나" 즉시 보임.

## 🧭 주요 의사결정

### 1. **Q1=B (registry-derived refinement)** — 사용자 결정 (2026-04-28)

### 2. **Q2=C (좁은 검증, 깊은 검증 deferred)** — 사용자 결정
field 이름만 등록 set 검증. operator/value type 깊은 검증은 [3-46] deferred. 이유: queryableFields 메타데이터 풍부화 + Zod superRefine 1.5h 추가 작업이 Step 4 scope 폭증 위험.

### 3. **Q3=A (fallbackReason 2분할)** — 사용자 결정
discriminatedUnion 도메인 묶음 (대안 b) 대신 enum 평면 확장. 이유: 변경 면적 최소 (5 파일 만 영향), `log_chat.fallback_reason VARCHAR(40)` 호환 (모두 ≤ 12자), `messageForReason` switch exhaustiveness 그대로 유지.

### 4. **commonFields 패턴 B (머지)** — crypto-domain-expert 자문 채택
`exchange/market_type/symbol` 3 PK 를 1곳 정의 + 9 datasource 자동 상속. 이유: 새 datasource 추가 시 boilerplate 0, 변경 1곳, AI 입장에서는 머지된 view 만 봐서 명시성 동일.

### 5. **AiCardConfigSchema 최상위 superRefine (옵션 a)** — zod-schema-architect 자문
`.transform()` (옵션 b) 또는 `discriminatedUnion("datasource")` (옵션 c) 대신 최상위 `superRefine`. 이유: cross-field 검증이 직선적 (datasource 와 filters 같은 스코프), `path` 정확히 명시 가능 → AI self-correction retry 효율 ↑.

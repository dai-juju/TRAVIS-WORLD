## 📖 비전공자 친화 설명

Step 2에서 4장의 빈 메뉴판 형식을 만들었습니다. Step 3에서는 각 메뉴판에 **샘플 메뉴 1개씩**을 실제로 적어본 것입니다.

사용자와 협의한 대로, 샘플은 완전 가짜(`dummy`)가 아니라 **Binance를 기반으로 한 현실적 메타데이터**입니다:
- 거래소 메뉴판: "Binance / spot+선물(USDM) / api.binance.com / WS 9443 포트 / 배치 지원"
- 데이터소스 메뉴판: "Ticker 24h / _now 카테고리 / 높은 갱신주기 / 필터 가능: 거래량·변동률·현재가"
- 컴포넌트 메뉴판: "실시간 가격 카드 / sm·md 사이즈 / value 모드 / ticker 데이터 필요"
- 인터랙션 메뉴판: "새 카드 생성(spawn) / 파라미터: 대상 컴포넌트ID + 심볼"

이렇게 해두면 M1.3에서 실제 Binance 어댑터를 구현할 때 이 샘플을 **그대로 확장**하면 됩니다.

기술적으로, `defaults.ts`라는 파일에 4건의 등록 코드를 모았고, 레지스트리 배럴을 import하면 자동으로 등록됩니다(사이드이펙트 import 패턴).

## 🧭 주요 의사결정 (2건)

1. **별도 `defaults.ts` 파일 사용 (각 레지스트리 파일 하단에 등록 거부)**: 등록 코드를 한 곳에 모아두면 "현재 무엇이 기본 등록되어 있는가"를 한눈에 파악 가능. M1.3에서 실제 항목 추가 시에도 이 파일을 확장하면 됨.

2. **사이드이펙트 import 패턴 사용**: `import "./defaults.js"`만 하면 자동 등록. 명시적 호출이 필요 없어 사용 실수 방지.

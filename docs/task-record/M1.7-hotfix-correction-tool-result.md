# M1.7 Hotfix — self-correction 재시도가 항상 Anthropic 400 으로 죽던 잠복 버그

**날짜**: 2026-05-04
**소요 시간**: ~30분
**커밋**: (이 commit)
**트리거**: 사용자가 Vercel 배포본에서 직접 사용 중 발견 — "The AI service didn't respond. Please try again shortly." 토스트가 반복 노출.

---

## 1. 증상

Vercel runtime log:

```
[orchestrate] 2회 실패 (haiku_call): Anthropic 전송 실패: Anthropic API 호출 실패:
400 {"type":"error","error":{"type":"invalid_request_error",
"message":"messages.2: `tool_use` ids were found without `tool_result` blocks
immediately after: toolu_..."}}
```

→ `transient_error` fallback → 사용자에겐 재시도 권유 토스트.

## 2. 원인

`apps/web/app/api/orchestrate/route.ts:345-360` 의 self-correction 재시도 messages 구성이
Anthropic API 의 핵심 invariant 를 위반:

> **assistant turn 에 `tool_use` 블록이 있으면, 다음 user turn 은 반드시 `tool_result`
> 블록으로 시작해야 한다. 일반 텍스트면 400 invalid_request_error.**

기존 retry messages 모양:
```
[
  user("원쿼리"),
  assistant([{ type: "tool_use", id: "toolu_xxx", ... }]),
  user("Your previous response failed validation: ...")  ← 여기가 invariant 위반
]
```

USE_TOOL_USE=true (현재 default) 환경에서 1차 호출이 Zod 실패 (`schema_drift` /
`parse_error`) 로 떨어지면 retry 가 100% 400 으로 죽음.

### 왜 잠복했나

`orchestrateOnce.test.ts (g) correction 컨텍스트` 단위 테스트가
**fixture `makeFakeMessage({ stop_reason: "tool_use" })` 로 `content: []` (빈 배열)** 만
검증해서 production 시나리오 (`content: [{ type: "tool_use", ... }]`) 와 괴리.
즉 mock 은 "코드가 의도한 messages 모양" 만 검증하지 "Anthropic 이 받아들일지" 는
모름. mock-기반 테스트의 일반적 한계.

## 3. 수정

### 3.1 `apps/web/app/api/orchestrate/route.ts`

- 신규 헬퍼 함수 `buildCorrectionMessages(query, correction): Anthropic.MessageParam[]`
  추가. 다음 분기:
  - assistant content array 에서 첫 번째 `tool_use` 블록 추출.
  - **tool_use 발견 시** → user turn content 를 `[{ type: "tool_result",
    tool_use_id: <발견된 id>, content: <correction 메시지>, is_error: true }]`
    array 로 구성 (invariant 만족).
  - **tool_use 없음** (text-only fallback / USE_TOOL_USE=false) → 기존 string
    content 유지.
- `orchestrateOnce` 내부의 inline messages 구성을 헬퍼 호출로 단순화.

### 3.2 `apps/web/lib/ai/__tests__/orchestrateOnce.test.ts`

- (g) 기존 케이스 강화 — fakePrev 가 실제 `tool_use` 블록을 포함하도록 fixture 변경.
  user turn content 가 `tool_result` block array 로 짝지어지는지 단언 (회귀 방지선).
- (g2) 새 케이스 추가 — tool_use 가 없는 fallback 경로 (text-only) 에서는 string
  content 유지되는지 단언 (정상 동작 가드).
- `ORCH_TOOL_NAME` import 추가.

## 5. 후속 deferred

- **mock-기반 테스트 한계**: live Anthropic SDK call 로 self-correction 경로 E2E
  검증 케이스 추가 필요. 1회 호출 = 약간의 토큰 비용. M2+ 로 미룸.
- **transient_error 의 과적재**: 401/402/429/5xx/timeout 을 모두 같은 enum 으로
  묶어 사용자에게 "재시도 권유" 메시지를 냄. 401 (auth) / 402 (insufficient credit)
  은 영구 문제인데 잘못된 안내. M1.7 또는 M2 에서 status code 별 fallbackReason
  세분화 후보.

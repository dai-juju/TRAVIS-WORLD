## 0. 한 줄 요약 (비전공자용)

**수돗물 관 안에 낡은 찌꺼기(상장폐지 코인 데이터) 가 쌓여 있었고, 수도꼭지(카드) 에서 이상한 색 물(극단값) 이 섞여 나온 상황**. 원인은 세 갈래: (1) 바이낸스가 상장폐지 진행 중인 코인도 WebSocket 에 계속 푸시하는데 우리가 그대로 받아 DB 에 넣었음, (2) 우리 심볼 마스터가 초기 1회만 로드되고 재동기화 안 됐음, (3) 거래량 변화율 계산이 서버 부팅 직후 부족한 데이터로 잘못된 값을 만들었음. 전부 고쳐서 이제는 **바이낸스 공식 TRADING 상태인 심볼만** DB 에 업데이트되고, 거래량 변화율은 5분 분량 데이터가 모일 때까지 null 로 표시, ±50% 벗어나면 자동 숨김.

### 문제 2 — BTCUSDT VOL 5M -53.03% 극단값

**관찰**: "VOL 5M -53.03% (근사)". 정상 거래량이 5분 내 절반으로 떨어지는 건 비정상.

**원인**: `preComputeTicker` 의 해석 A fallback 이 RollingWindow 워밍업 부족(1~4 분) 시점에 호출되면 "5분 전" 이 실제로는 1~2분 전 샘플이라 차분이 왜곡됨.

## 2. 근본 원인 분석 (Binance 공식 문서 근거)

Binance 공식 contract status enum (context7 `/websites/developers_binance_zh-cn_derivatives`, 2026-04-22 조회):

| Status | 의미 | 거래 가능 |
|---|---|---|
| PENDING_TRADING | 상장 대기 (待上市) | ✗ |
| **TRADING** | 거래 중 (交易中) | **✓** |
| PRE_DELIVERING | 인도 전 (预交割) | ✗ |
| DELIVERING | 인도 중 (交割中) | ✗ |
| DELIVERED | 인도 완료 (已交割) | ✗ |
| PRE_SETTLE | 정산 전 (预结算) | ✗ |
| SETTLING | 정산 중 (结算中) | ✗ |
| CLOSE | 상장폐지 (已下架) | ✗ |

**함정**: Binance `!miniTicker@arr` WS stream 은 **TRADING 아닌 심볼도 계속 푸시**. 클라이언트(worker) 에서 allowlist 필터 필수.

## 3. 적용한 수정 (4개 파일)

### 3-A. `apps/worker/src/ws-relay/streams/tickerWsHandler.ts`
- `TickerWsHandlerDeps.tradingSymbolsByMarket?: Record<MarketType, Set<string>>` 신규

### 3-B. `apps/worker/src/index.ts`
- `tradingSymbolsByMarket` Set 3종 생성 (spot/usdm/coinm)
- `createTickerWsHandler` 에 주입
- **24h 주기 `setInterval` 로 `loadAllSymbols()` 재실행 → Set 내용 in-place swap** — 참조는 유지해 핸들러가 자동으로 최신 값 조회
- `shutdown` 에서 `clearInterval(symbolRefreshTimer)`

### 3-C. `apps/worker/src/compute/preCompute.ts`
두 가지 가드 추가:
1. **워밍업 가드**: `tickerWindow.getRecent(symbol, STEPS["5m"]).length >= 5` 확인 후에만 해석 A fallback 계산. 미달 시 `volume_chg_5m = null`.
2. **극단값 sanity clip**: 해석 A 결과 `|volumeChg5mFallback| > 50` 이면 null. 해석 B (실제 1m kline 합 비교) 는 실데이터라 clip 하지 않음.

### 3-D. `.claude/CLAUDE.md`
신규 섹션 **"데이터 소스 위생 원칙 (필수)"** — 8개 체크리스트. 신규 거래소/지표 adapter 추가 시 모든 항목을 PR/task-record 에 기록 의무화.

### 3-E. Supabase SQL (사용자 수동 실행)
```sql
DELETE FROM public.now_futures_ticker WHERE (exchange, market_type, symbol) IN
  (SELECT exchange, market_type, symbol FROM public.symbols WHERE status != 'TRADING');
-- now_spot_ticker / now_futures_indicator 동일
```

## 6. 알려진 잔여 이슈 (Step 5 이월)

- **중국어 밈 심볼** (`币安人生USDT`, `我踏马来了USDT`) 이 실제 TRADING 중 — Binance 의 meme coin 상장 자체가 정상. UI 렌더에는 문제없지만 프론트 검색/입력 시 한자 입력 UX 고려 필요 (M1.5+ UX 폴리싱).
- **log_validation_failure 테이블에 "Symbol is on delivering" 로그 축적** — worker REST per-symbol task 가 SETTLING 심볼 이미 skip 하지만 일부 edge case 에서 여전히 호출 시도. M1.5 `@backend-infra-specialist` 재검토 대상 (미치명).
- **volume_chg_5m 해석 B (1m kline 합) vs 해석 A (24h 롤링 차분)** 전환 타이밍 — 현재 Step 5e 기반으로 해석 B 우선이지만 kline WS 연결 중단 시 해석 A 로 fallback. M1.5 에서 데이터 신선도 배지 도입 시 두 해석의 차이를 사용자에게 표시 고려.

## 📖 비전공자 친화 설명

Step 2~4에서 만든 레지스트리는 "AI에게 무엇이 가능한지 알려주는 메뉴판"이었습니다. Step 5는 "실제 요리사(개발자)가 새 요리를 만들 때 따라야 할 레시피 표준"을 정의한 것입니다.

3개의 "계약서"를 만들었습니다:
1. **IExchangeAdapter** — "거래소에서 데이터를 가져오는 법" 계약. 반드시 배치로 가져와야 하고(한 번에 전체 코인), 심볼 하나씩 가져오는 건 금지.
2. **IWsRelay** — "거래소의 실시간 스트림을 프론트에 중계하는 법" 계약. 연결 끊기면 자동 재연결.
3. **IPoller** — "주기적으로 데이터를 수집하는 법" 계약. 높음/중간/낮음 3단계 주기.

이 계약서가 있으면 M1.3에서 Binance 어댑터를 만들 때 "어떤 함수를 어떤 형태로 만들어야 하지?"를 고민할 필요 없이, 계약서대로 채우기만 하면 됩니다. 나중에 OKX, Bybit 어댑터도 같은 계약서로 만듭니다.

## 🧭 주요 의사결정 (2건)

1. **FetchResult를 discriminated union으로 구현**: `{ success: true, data: T } | { success: false, error: string }` — TypeScript가 `if (result.success)` 분기에서 자동으로 타입을 좁혀줌. try-catch보다 명시적이고 graceful.

2. **RawTicker/RawKline에 index signature 사용**: `[key: string]: unknown` — 구체 필드는 M1.3에서 Binance API 응답을 보고 확정. deferred decision 원칙.

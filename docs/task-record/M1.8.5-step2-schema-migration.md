## 1. 배경

M1.8.5 Step 3 의 fetcher 6종 (D21=B) 이 `history_futures_indicator` 에 6 metric × **9 interval (5m/15m/30m/1h/2h/4h/6h/12h/1d) × 608 symbols × 14일 = 25M row** 을 적재하려면 동일 `recorded_at` timestamp 의 5m / 15m / 1h 봉이 충돌 없이 공존해야 함. 기존 schema 는 `id BIGINT IDENTITY` surrogate PK + 4축 non-unique INDEX 뿐이라 자연 키 강제 부재 → ON CONFLICT upsert 패턴 불가능.

본 Step 의 결정 = **D22=A 채택** (2026-05-27 사용자 확정): `interval VARCHAR(5)` NOT NULL 컬럼 ADD + 5축 자연 키 UNIQUE INDEX 신설. id PK 그대로 유지 (fact-table 패턴).

## 3. 적용 SQL (D22=A 3단)

```sql
-- 1. interval 컬럼 추가 (NOT NULL + 임시 DEFAULT)
ALTER TABLE public.history_futures_indicator
  ADD COLUMN interval VARCHAR(5) NOT NULL DEFAULT '1d';

-- 2. 자연 키 5축 UNIQUE INDEX 신설
CREATE UNIQUE INDEX history_futures_indicator_natural_pk
  ON public.history_futures_indicator (exchange, market_type, symbol, interval, recorded_at);

-- 3. DEFAULT 제거 → 이후 INSERT 시 interval 명시 강제
ALTER TABLE public.history_futures_indicator
  ALTER COLUMN interval DROP DEFAULT;
```

## 8. 영구 영향 의사결정

- **fact-table 패턴 채택**: surrogate PK + natural key UNIQUE INDEX + non-unique lookup INDEX 3축 = OLAP 시계열 표준. 향후 `history_*` 신규 테이블 (M1.9 COINM history / M2 OKX history) 도 동일 패턴 미러링 권고.
- **VARCHAR(5) 선택 근거**: 9 interval 최대 길이 = `'15m'` / `'30m'` / `'12h'` 등 3자 (`'5m'` 2자 / `'1d'` 2자 포함). VARCHAR(5) = 안전 마진 + 미래 확장 (예: `'30d'` / `'1w'`) 여지.
- **DEFAULT 패턴**: ADD COLUMN NOT NULL 직접 = 기존 row 가 있는 경우 fail. row 0이라 직접 가능했지만 표준 패턴 (DEFAULT 임시 → DROP DEFAULT) 준수 → 미래 row 가 있는 환경에서 동일 SQL 재실행 가능.

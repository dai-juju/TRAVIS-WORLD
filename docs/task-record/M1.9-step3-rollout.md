## 라이브 실측 이슈 3건 (가동 중 적발)

### 이슈 1 — `getMaxRecordedAt` freshness 조회 25초 statement timeout → ✅ 해소
- **증상**: 첫 cycle에서 `[forwardFill:usdm-long] 12h freshness 조회 실패(skip): canceling statement due to statement timeout`.
- **원인** (EXPLAIN ANALYZE 실측): `(exchange, market_type, interval)` 필터 + `recorded_at DESC LIMIT 1` 쿼리가 기존 `natural_pk(exchange, market_type, **symbol**, interval, recorded_at)`로는 symbol 조건 부재 → 608 심볼 전수 스캔 + top-N sort = **24,996ms**. (코드 주석의 "저빈도라 부담 낮음" 가정이 빗나감 — 빈도 무관 인덱스 부적합.)
- **fix**: `(exchange, market_type, interval, recorded_at DESC)` 전용 인덱스 신설 (`20260604000001_m1_9_step3_freshness_index.sql`). **25초 → 5.861ms** (Index Only Scan, Heap Fetches 1). 기존 인덱스 3개 전부 보존(ADD not DROP). `docs/DB_SCHEMA.md` 갱신.
- ⚠️ Supabase MCP가 read-only mode라 인덱스 생성은 **사용자가 Dashboard SQL Editor에서 `SET statement_timeout='600s'` + CREATE INDEX** 직접 실행. 검증(EXPLAIN)은 Claude가 read로 수행.

### 이슈 2 — `/futures/data/basis` -1003 ban (별도 IP인데도) → 즉효 fix(피크 완화)
- **증상**: catch-up 중 basis에 집중된 `-1003`(418 IP ban / 429 "2400 req/min"). 다른 5 metric은 통과.
- **원인** (crypto-domain-expert 확정, 공식 change-log 2023-10-19): `basis`만 "1000 req/5min" 별도 카운터 조정 목록에서 **빠져** 일반 fapi weight 풀(2400/min)에 걸림. + (backend-infra) throttle이 task별 독립 클로저 → 3 task 0ms 동시 발화 합산 + 첫 catch-up(4일) 페이지 폭발 + 재시도 증폭. 메시지의 `10.119.x.x`는 Binance 내부 LB 라벨(우리 공인 IP에 실제 ban). **production worker(178.x) 무관**.
- **즉효 fix**: basis 전용 2400ms floor(25/min) + task staggered start(0/30/60s) + (이슈3 공통) TimeoutStopSec.
- ⚠️ code-reviewer W1: basis floor는 단일 클로저 공유라 "prev→basis 간격"을 벌림(과하게 안전 — basis-to-basis는 더 넓어짐). 부작용 = **cycle이 심볼 수 × 2400ms 팽창**(USDM ~450심볼 → interval당 +~18분). catch-up 동안만, tier=low라 허용. 근본 fix(per-metric lastCallAt)는 `[8-31]`.

### 이슈 3 — graceful shutdown 90초 초과 → SIGKILL → `failed` → 즉효 fix
- **증상**: `systemctl stop` 시 `executeHistoryBackfill` 진행 중이라 SIGTERM 후 90초(systemd 기본) 초과 → SIGKILL → `Failed with result 'timeout'`.
- **원인**: unit `TimeoutStopSec` 미설정 + `executeHistoryBackfill`에 abort 신호 없어 cycle(수분)을 중간에 못 끊음. 데이터 손상은 없음(멱등).
- **즉효 fix**: `KillSignal=SIGTERM` + `TimeoutStopSec=180`(증상 완화). 근본 fix(AbortSignal 협조적 취소)는 `[8-31]`.

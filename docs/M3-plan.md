## 1. M3 정의와 경계

**정의**: 신규 데이터 **공급자(provider)** 추가 전, **Binance 데이터만으로** — 모든 데이터 × 모든 형태 × **모든 인터랙션** + 고도화 + UIUX 다듬기를 완성하는 마일스톤.

**경계 = 공급자(provider) 기준** (2026-07-15 사용자/CTO 정밀화 — "데이터소스 개수"가 아님):
- ✅ **IN**: Binance 라는 공급자 안에서의 datasource 추가는 자유 — 알파(Alpha) 마켓, 체결/호가(ff#3), 추가 metric, 바이낸스가 주는 더 다양한 정보 전부.
- ❌ **OUT (M4 벽)**: 새 공급자 — CMC/CoinGecko(메타·로고), 뉴스, OKX/Bybit/Bitget, 온체인. 이들의 선행 리팩터(`[8-27]` #1~#4 비-거래소 배관 / #5·#6 거래소 2개째 + `[10-107]` 파일 분할)도 M4 벽 앞에서 수행 (지금 하면 YAGNI).

**영구 원칙 재확인 (사용자 2026-07-15, 계획 항목 ⑧)**: 어떤 데이터소스를 추가하든 **가능한 모든 컴포넌트와 인터랙션으로 표현 가능**해야 한다 (= PRD §2 최상위 축 + 인터랙션까지 명시 확장). 인터랙션 wire 는 form 레벨에 걸려 새 datasource 에 자동 적용되도록 설계한다.

## 2. 계획 세션 결정사항 (2026-07-15, 사용자 확정)

1. **뉴스/CMC 등 신규 공급자는 M3 완료 후** — Binance 만으로 할 수 있는 모든 것 + 고도화 + UIUX 를 먼저 (확장 시 용이한 구조 확보 겸).
2. **축 우선순위 = 표현력·실시간·인터랙션** (기존 축 1·2·3) — 세부는 사이클 착수 시 논의. 실사용 병렬 계속 (본 문서 §6 이 기록처).
3. **인터랙션 wire 는 빠르게** — M3 **첫 사이클로 확정**. 확장성 필수(새 datasource 자동 작동).
4. 상시 기술부채·운영/신뢰성도 중요 — 트랙 ⑤ 로 사이클에 동반 회수.
5. **베타 로드맵**: Binance 완성(M3) → 신규 공급자(M4: CMC·뉴스) → **베타테스터 모집 전 선행 = 100명 감당 스케일링(Supabase/Hetzner/Vercel) + 보안 + 전체 코드 리뷰·정리**(M5, = M1.7 Closed Beta Ops 활성화 포함).
6. **M3 명명 + 본 문서 신설** — M2 문서 2종 마감·이관 (§7).
7. **바이낸스 알파(Alpha) 코인 + 바이낸스 내부 추가 데이터** = M3 트랙 ③ (착수 전 `@crypto-domain-expert` 공식 API 조사 선행 — 알파 존 공개 API 형식 미확인 상태, 위생 #1/#8).
8. 원칙 ⑧ = §1 에 명문화.

**역질문 확정 3건**:
- **세션 컨텍스트("거기에 ETH 추가") + 혼합 응답(카드+보조 텍스트) = 둘 다 보류** — M3 범위 제외, `future.md §4/§3` 토론용 유지, 수요 재실증 시 재논의.
- **OKX 등 타 거래소 = 미정** — 베타~Launch 사이 재논의 (Launch §L.1 `[6-1]` "거래소 최소 2개" 요건이므로 Launch 전엔 필수. 베타는 Binance 단독 가능).
- **첫 사이클 = 인터랙션 wire** (+ UX 즉결 웜업 5건 포함).

**같은 세션 부수 종결**: Supabase Realtime quota — 현 주기(6/21~7/21) 2.52M/5M(50%) 실측, 초과 없이 통과 확정적, 조치 불필요 (`task-record/M2-[10-77]-realtime-throttle.md` G3+ 실측). 부산물 = `[10-86]` ticker coalescing "다음 워커 작업 동반 후보" 승격 (베타 스케일 M5 의 핵심 선행이기도 함 — 활성 세션 하루 최대 ~760K 메시지 실측: 100명이면 현 구조로 월 5M 즉시 초과).

## 📖 비전공자 친화 설명

Step 3~4에서 본채(웹)와 별채(워커)에 콘센트를 매립했지만 전선은 연결 안 한 상태였습니다. `supabase.ts`라는 "콘센트 어댑터"가 있어도, 실제 전기(환경변수 = Supabase URL + 키)가 없으면 null(꺼진 상태)이었죠.

**Step 5에서 한 3가지**:
1. **전선 연결** — `.env.local`(웹용)과 `.env`(워커용) 파일에 Supabase 프로젝트의 실제 URL과 키를 적어넣었습니다. Supabase MCP 도구로 URL과 anon key를 자동으로 가져왔고, service_role key만 대시보드에서 직접 복사했습니다.
2. **전등 테스트** — 워커에서 `auth.admin.listUsers()`라는 관리자 API를 호출해서 "Supabase 서버가 응답하는지" 확인했습니다. `[supabase] worker connected to https://zvqvevwwtakjukdkdind.supabase.co`가 뜨면 성공. 웹에서는 `supabase` 클라이언트가 null이 아닌 실제 객체가 되면 `[supabase] web client ready` 로그가 뜹니다.
3. **전선이 바깥으로 나가지 않는지 확인** — `git status`에 `.env` 파일이 절대 나타나지 않고, `apps/web` 디렉토리에 `SUPABASE_SERVICE_ROLE_KEY`라는 문자열이 0건인 것을 grep으로 검증했습니다.

이 과정에서 **첫 번째 작은 파동**이 있었습니다. 처음에는 `auth.getUser()`로 ping을 시도했는데, "Auth session missing!" 에러가 떴습니다. 이건 연결 실패가 아니라 "로그인한 사용자가 없다"는 정상 응답이었지만, 로그에 "ping failed"로 찍히니 혼동을 줬습니다. service_role 전용 관리자 API인 `auth.admin.listUsers()`로 변경해서 깨끗하게 해결.

**추가 보강**: Supabase 공식 문서(context7)가 서버 환경에서 `persistSession: false`, `autoRefreshToken: false`, `detectSessionInUrl: false` 3개 옵션을 "crucial"로 권장합니다. 워커의 `supabase.ts`에 이 옵션을 추가해서, 백그라운드에서 불필요한 Auth 로직이 실행되는 것을 차단했습니다.

- **worker `index.ts`에 Supabase ping 추가** — `import { supabase } from "./supabase.js"` (NodeNext `.js` 확장자) + `auth.admin.listUsers({ perPage: 1 })` 호출. 테이블 없이도 동작하는 service_role 전용 ping.
- **web `supabase.ts`에 성공 로그 추가** — env 주입 시 `[supabase] web client ready` 브라우저 콘솔 출력. SSR에서는 `typeof window` 가드로 조용히.

## 🧭 주요 의사결정 (4건)

1. **env 로드 = `tsx --env-file=.env` (dotenv 패키지 거부)** — Node 20.6+/tsx 4.x 내장 기능. 의존성 0개. Step 4 task-record에서 이미 이 방식을 권장했고 그대로 실행.

2. **worker ping = `auth.admin.listUsers()` (`auth.getUser()` 거부)** — `getUser()`는 "현재 로그인 사용자" API라서 service_role 단독으로는 "Auth session missing!" 에러 반환. `admin.listUsers()`는 service_role 전용 관리자 API로 세션 없이 동작. `{ users: [], error: null }` = 연결 성공.

3. **web ping = 클라이언트 초기화 로그만 (DB 쿼리 거부)** — `supabase.ts`는 모듈 최상위 실행이라 `await` DB 쿼리 시 SSR 빌드 타임 부작용. `supabase !== null` = env 주입 성공으로 충분.

4. **legacy anon key 사용 (새 `sb_publishable_` 형식 거부)** — `@supabase/supabase-js` v2의 `createClient()`는 JWT 기반 legacy key와 100% 호환. 새 형식(`sb_publishable_`, `sb_secret_`)은 SDK 호환 불확실. 사용자에게 차이 설명 후 legacy key 채택.

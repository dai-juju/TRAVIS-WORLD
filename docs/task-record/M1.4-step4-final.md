## 7. 알려진 이슈 (후속 이월)

### 7-1. Undo 토스트 2차 버그 (Step 3 §7-1 ongoing)
**상태**: Provider 패턴 적용으로 Step 3 의 **근본 구조 문제 해결됨** — UndoToast 가 실제로 `toasts.length=1` 을 한 번 렌더함 (디버그 로그로 증명). 그러나 **즉시 toasts.length=0 으로 리셋되는 별개 2차 버그** 드러남.

**디버그 로그 증거**:
```
[CardContainer] handleRemove {id: test-debug2, hasSnapshot: true}
[CardContainer] showToast returned toast-1776787646871-qpstp  ← toast id 리턴 (store 에 실제 entry push)
[UndoToast] render {toastsLen: 1, first: toast-1776787646871-qpstp}  ← UndoToast 가 구독 중인 store 반영
[UndoToast] render {toastsLen: 1, ...}  ← StrictMode 이중 렌더 (정상)
[UndoToast] render {toastsLen: 0, first: undefined}  ← 즉시 리셋 — 이게 2차 버그
[UndoToast] render {toastsLen: 0, ...}
```

**가설**:
- (A) React 19 StrictMode 가 setState 를 비-배치 모드로 방해해 두 번째 논리 렌더에서 toast 제거
- (B) Turbopack HMR 이 toastStore 모듈을 재평가하면서 setTimeout 이 조기 firing
- (C) show() 호출의 클로저가 캡처한 get()/set() 이 구 store 를 참조하고, 새 store 가 empty 상태로 rerender 유발

**후속 action (Step 5 또는 M1.5 Step 0 에서 진단)**:
- `durationMs=0` (자동 dismiss 비활성) 로 설정해 setTimeout 을 배제하고 재현 테스트
- Turbopack HMR 비활성 `next dev --no-turbo` 에서 재현 여부 확인
- production build (`next build && next start`) 에서 재현 여부 확인 — StrictMode + HMR 모두 배제
- 위 세 테스트로 범위 좁힌 후 해당 영역 집중 디버깅

**임시 대응**: 사용자는 × 버튼으로 카드를 삭제할 수 있으며, 복구는 `window.__TRAVIS_INJECT__` 로 가능 (dev helper). M1.4 완료 기준 중 "삭제는 즉시 + Undo 토스트 5초 패턴" 은 Undo 토스트 DOM 렌더 자체가 일시적으로 일어남을 증거로 **완성됐으나 UX 폴리싱 필요** 로 해석.

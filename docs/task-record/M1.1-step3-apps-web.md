## 📖 비전공자 친화 설명

Step 1·2가 "땅 고르기 + 작은 창고 두 개"였다면, **Step 3은 본채(사용자가 실제로 보는 웹 화면)에 골조 + 전기·수도 배관 + 다크 톤 벽지를 한 번에 깐 단계**입니다. 비유하자면 모델하우스 오픈 직전, 가구는 없지만 손님이 들어와도 "여기는 TRAVIS구나"가 느껴지는 빈 방.

조금 풀면 이렇습니다. **3a**에서는 Next.js 16(웹 화면을 만드는 도구)을 띄워 `localhost:3000`에 빈 페이지가 뜨는지만 확인했어요. 흰 배경에 글자만. **3b**에서는 Tailwind v4(벽지·타일을 유틸리티 클래스로 바로 붙이는 도구)와 shadcn/UI의 zinc 팔레트(다크 회색 가구 세트)를 깔아서 화면이 zinc-950 다크 배경 + 중앙에 "TRAVIS — Shape your market" 한 줄로 바뀌었습니다. **3c**에서는 세 개의 배관(`supabase.ts`·`data.ts`·`store.ts`)을 미리 벽 속에 매립했어요 — 지금은 아무도 안 쓰지만 M1.3·M1.4 consumer가 생기는 즉시 꺾쇠 하나만 돌리면 흐름이 살아납니다. **3d**에서는 모든 검증(타입·린트·prettier·production build·Playwright 시각·git 누출 0건)을 통과시키고 청소를 했습니다.

핵심 설계 원칙이 여기서 모두 지켜졌어요: **crash 금지**(env 없어도 `lib/supabase.ts`가 null 반환 + warn), **서버/클라 경계 분리**(`app/`에 `"use client"` 0건, `lib/store.ts`만 client), **확장 포인트를 placeholder로 선-예약**(`dataService = null`은 M1.3에서 인스턴스 주입 1줄로 살아남), **dataService 추상화 layer 경유 의무**(`@travis/data-service`가 runtime-agnostic, `apps/web/lib/supabase.ts`는 브라우저 env 주입자라는 책임 분리). 이 분리는 M1.6에서 `@supabase/ssr`로 교체할 때, 그리고 워커가 service_role로 별도 클라이언트를 만들 때 한 번에 회수됩니다.

이번 단계에서 작은 파동이 두 번 있었어요. 첫째, ESLint 9 + `eslint-config-next` v16 조합에서 처음에 `@eslint/eslintrc`의 FlatCompat 패턴으로 시작했다가 "Converting circular structure to JSON" 에러가 터졌습니다. 실제 패키지를 까보니 **`eslint-config-next` v16은 네이티브 flat config를 default-export**하는 형태였어요. FlatCompat 제거 + `/core-web-vitals`·`/typescript` 두 subpath를 `import + spread`하는 공식 패턴으로 바꿔서 해결. 둘째, code-reviewer가 "**`apps/web/.prettierrc`는 루트 `.prettierrc`를 상속이 아니라 override**한다"고 짚어줘서, 루트 포맷 규칙(printWidth 100, trailingComma all, endOfLine lf 등)이 apps/web에서 사라진 상태였습니다. 루트 규칙을 명시적으로 복사·합쳐서 fix. 둘 다 작은 차이지만, "최신 라이브러리는 일단 실제 export부터 까본다" + "monorepo prettier는 가장 가까운 config 1개만 선택된다"는 두 교훈을 첫 화면 작업부터 심어둔 셈입니다.

## 🧭 주요 의사결정 (3건)

1. **ESLint flat config 패턴: `FlatCompat` 대신 native subpath spread** — 초기엔 Plan 에이전트가 "FlatCompat 불필요, native spread"를 권고했으나 안전을 위해 FlatCompat로 시작했다가 "circular structure" 에러로 실패. 실제 `node_modules/eslint-config-next/dist/index.js`를 까보니 v16은 `module.exports = config;` 형태로 네이티브 flat 배열을 default-export. `FlatCompat`가 이 배열을 다시 legacy 변환하다 무한 참조 발생이 원인. **교정**: `import nextCoreWebVitals from "eslint-config-next/core-web-vitals"`처럼 subpath별 default import → spread. `@eslint/eslintrc` devDep 제거. **이유**: 공식 패키지의 실제 export 형태를 따르는 게 가장 호환성 높음 + 의존성 1개 절약.

2. **`globals.css`의 `@theme inline` 사용 결정** — 원안 플랜은 "@theme CSS-first 커스터마이즈 사용 안 함(M1.4로 이월)"이었으나 shadcn CSS 변수(`--background` 등)를 Tailwind 유틸리티(`bg-background` 등)로 노출하려면 `@theme inline { --color-background: var(--background); }` 브릿지가 **필수**. 이는 "브랜드 색 커스터마이즈"가 아니라 "shadcn ↔ Tailwind 변수 연결 라우터" 역할. **교정**: `@theme inline` 블록을 globals.css에 포함하되, 브랜드 토큰(암호화폐 차트 green/red 등) 추가는 M1.4로 이월.

3. **루트 `.prettierrc` 상속 함정 fix** — code-reviewer W1 지적: `apps/web/.prettierrc`가 존재하면 Prettier는 루트 설정을 상속하지 않고 **완전히 override**. 이 상태에서 prettier check가 우연히 clean 판정이 났던 이유는 단순히 Prettier 기본값과 충돌이 없었던 것. **교정**: 루트의 10개 옵션(semi, singleQuote, trailingComma, printWidth, tabWidth, useTabs, arrowParens, bracketSpacing, bracketSameLine, endOfLine)을 apps/web `.prettierrc`에 명시 복사 + Tailwind plugin 2줄 추가. `prettier --write` 1회로 3개 파일(page.tsx, supabase.ts, tsconfig.json) 재포맷 후 clean. **이유**: 향후 다른 개발자/에디터 환경에서 대량 diff가 폭발하는 함정 차단.

4. **crypto-trader Q1+Q3 fix 즉시 반영, Q2 M1.4 이월** — Phase 4 advisory에서 트레이더 페르소나(스캘퍼·스윙·시그널 운영자) 시각으로 3개 결정 질문이 나왔음. **Q1**(`tabular-nums`)·**Q3**(모바일 `px-6`)는 비용 0 + 부작용 0 + M1.4에서 어차피 결정해야 할 토큰 → 즉시 채택. **Q2**(zinc-950 vs zinc-900) 결정은 OBS 저비트레이트 송출에서 순흑 배경의 밴딩 노이즈 실측이 필요하고, KlineChartCard 도입 시 실데이터 + OBS 시나리오로 함께 결정하는 게 정확 → M1.4 이월. **이유**: "지금 넣어도 손실 0인 토큰만 추가, 실측 필요한 톤 결정은 적절한 시점에 한 번에" 원칙. Step 3 scope 경계와도 정합(M1.4 React Flow + 실 카드 시점에 본격 UI 결정).

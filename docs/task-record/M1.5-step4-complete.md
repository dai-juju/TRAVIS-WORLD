## 0. 한 줄 요약 (비전공자용)

**"말로 화면을 조립한다"는 TRAVIS 의 핵심 비전이 E2E 로 최초 증명되었고, 동시에 두 개의 구조적 결함을 찾아 근본 해결했다.** Step 4 는 식당으로 치면 "주방 건강검진": 주문(쿼리) → 주방장(Haiku AI) → 메뉴판(registry) → 서빙(카드 렌더) 까지 모든 구간을 유리관처럼 투명하게 만들어 어디서 새는지 검사하는 단계. 그 과정에서 **"메뉴판에 안 올려진 요리를 주방장이 우연히 만들고 있던"** (coin-list-card/kline-chart-card registry 미등록) 과 **"같은 주문 두 번에 접시가 겹쳐 쌓이던"** (AI 가 결정적 id 반환 시 React Flow 덮어쓰기) 두 결함을 잡았다. 총 55 vitest + 5 Playwright 시나리오로 재현 가능한 형태로 고정.

## 3. 발견된 구조적 결함 2건 + 근본 해결

### 결함 1 — AI-facing component registry 누락

**발견**: Playwright 가 `"BTCUSDT 1-minute candlestick chart"` 쿼리를 보냈을 때 AI 가 ticker-card 로 잘못 매핑. 조사 결과 `packages/shared/src/registries/defaults.ts` 의 `registerComponent` 호출이 **ticker-card 하나만** 되어 있었음. `coin-list-card`/`kline-chart-card` 는 `apps/web/lib/registerCards.ts` (React 렌더 맵) 에만 등록, AI metadata 레지스트리에는 부재.

왜 (A) list 테스트가 통과했었는가: Haiku 가 `componentId` 자유 string 인 점을 이용해 환각으로 `coin-list-card` 를 출력 → 우연히 React registry 와 매칭 → 카드 렌더. **환각 의존성**. 이월 항목 `[3-7]` (datasource/componentId enum 승격) 의 실제 발현.

**근본 해결** (defaults.ts 재작성):
- `coin-list-card` / `kline-chart-card` 정식 `registerComponent` 등록
- 의미적 완결을 위해 `kline` datasource 신규 등록 (실 데이터는 TV widget 이 가져오지만 AI 에게는 "symbol+interval 을 요구하는 candlestick data source" 로만 노출)
- 전체 description 을 **영어로 재작성** + 각 component 가 **자기 유스케이스를 명확히 선언** ("Use when the user wants a visual price history (keywords they may use: chart, candle, kline, OHLC, timeframe)" 형식)

이 수정만으로 kline 쿼리가 정확히 kline-chart-card 로 매핑됨. 하드코딩 없이.

### 결함 2 — AI 결정적 id 로 인한 React Flow 덮어쓰기

**발견**: (E) 동일 쿼리 2회 테스트에서 카드가 1개만 보임. Haiku 가 `id: "ticker-btcusdt"` 같은 결정적 id 를 반환 → 2번째 카드가 같은 id 로 들어와 React Flow 가 덮어쓰기. 동시에 `layoutSlot` 이 dispatcher 호출 내 index 만 써서 시각적으로도 겹침.

**근본 해결** (actionDispatcher.ts):
- `resolveUniqueId(desired, taken)`: canvas 의 기존 id 와 충돌 시 short base36 nonce(6자) 자동 suffix. 10회 재시도 후 timestamp fallback.
- `layoutSlot` 에 `seedOffset = api.nodes.length` 반영 — 기존 카드 수만큼 그리드 이동 → 시각적 겹침 방지.

**원칙**: canvas 무결성은 AI 순응성(프롬프트로 "유일 id 내라" 요청)이 아니라 **dispatcher 레이어에서 구조적으로** 보장. LLM 이 어떻게 답하든 수용.

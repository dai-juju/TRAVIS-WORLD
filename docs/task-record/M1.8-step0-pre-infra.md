#### Q2. ★ funding rate 의 정체 (사용자 핵심 단서 검증)
- **`markPriceUpdate.r` = predicted next funding rate** (1초 변동). docs verbatim 표현은 "Funding rate" 라고만 적혀 있으나 1초 변동 거동 + 사이트 우상단 funding(4h) 박스 일치로 입증.
- **`premiumIndex.lastFundingRate` = realized (마지막 정산값)**. docs verbatim: "This is the Latest funding rate". 정산 직후 8h(또는 4h) 고정.
- **사이트 우상단 funding(4h) / Countdown 박스의 의미**: 큰 숫자 = predicted (1초 변동) + "(4h)" 라벨 = 해당 코인 interval + Countdown = `next_funding_time` 까지 남은 시간. Countdown=0 도달 순간 predicted 가 정산되어 realized 가 되고 다음 interval predicted 가 다시 1초 변동 시작.

#### Q3. ★ Funding interval 4h vs 8h 식별 — PHAROSUSDT 케이스 (실측 검증 완료)
- **`/fapi/v1/fundingInfo` endpoint 존재 확인** (weight 0):
  ```json
  {
    "symbol": "PHAROSUSDT",
    "adjustedFundingRateCap": "0.02000000",
    "adjustedFundingRateFloor": "-0.02000000",
    "fundingIntervalHours": 4,
    "disclaimer": false,
    "updateTime": 1778734037215
  }
  ```
- **default = 8h** — fundingInfo 응답에 없으면 8h fallback (negative-space 정의).
- **응답 전체 ~1,100~1,200 rows** — 4h/cap/floor 정의된 코인이 다수. 우리 USDM TRADING 608 중 상당수 포함.
- **`updateTime` 필드 (자문에 없던 추가 발견)** — 마지막 갱신 시각. reload 주기 결정에 활용 가능 (선택적).
- Countdown 데이터 소스 = `next_funding_time` 기반 클라이언트 계산 (`formatDuration(next_funding_time - Date.now())`).

- `contractType` 필수 파라미터: `PERPETUAL` 만 사용 (TRAVIS 는 무기한만 다룸).

  ADD COLUMN funding_interval_hours SMALLINT;

  'Binance fundingInfo.fundingIntervalHours. NULL = SPOT 또는 fundingInfo 미등재 = default 8h fallback.';

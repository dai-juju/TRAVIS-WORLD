## 📖 비전공자 친화 설명

**"우리 화면이 보여주는 숫자가 Binance 공식 사이트와 다르다" 는 트레이더 신뢰 깨짐 사고를 즉시 회수한 단계입니다.**

### 비유 — "신문 정정 보도"

신문이 어제 "BTC -0.28% 하락" 이라고 보도했는데, 실제 Binance 공식 시세는 "+0.80% 상승" 이었다고 가정합시다. 트레이더는 **"이 신문 못 믿는다"** 라고 판단합니다. 이게 Binance 공식 사이트의 진실과 우리 카드 표시 값이 1.08% 차이 + 부호 반대로 나타난 사건의 도메인 의미.

### 무엇이 잘못되었는가 (M1.3 Step 5b 잠복 버그)

M1.3 Step 5b (2026-04-19) 에서 worker 가 거래소 데이터를 받는 통로를 **REST 폴링 → WebSocket** 으로 바꿨습니다. 그때 **`!miniTicker@arr`** 라는 "간소화 ticker stream" 을 선택. 이름 그대로 mini 라 6 필드만 (가격 / 시고저 / 거래량) — **24시간 변화율은 빠짐**.

→ DB 의 `price_change_pct` (24h 변화율) 가 마지막 REST 폴링 (M1.3 Step 4 시점, 2026-04-19) 값으로 **영구 stale**. WebSocket 이 매초 가격은 갱신했지만 변화율은 손도 안 댐. 약 7일간 잠복.

### 사용자 발견 (2026-04-27)

사용자(트레이더)가 "top volume coin (top 10) in binance futures" 카드를 띄우고 Binance 공식 사이트와 비교 → BTCUSDT 가격은 일치 ($77,960), **변화율만 다름** (사이트 +0.80% vs 카드 -0.28%). 정확한 단서로 즉시 진단 가능.

### 해결 (옵션 A 채택)

WebSocket stream 을 **`!ticker@arr`** (full ticker, 17 필드) 로 전환:
- mini 6 필드 → full 17 필드 (`P` priceChangePercent / `p` priceChange / `w` weightedAvgPrice / `n` tradeCount / `O` openTime / `C` closeTime 추가)
- 매초 24h 변화율 실시간 적재 → **Binance 사이트와 1초 이내 일치**
- 페이로드 크기 ~3배 증가 (Hetzner 1Gbps 무시 가능)

### 가장 중요한 부수 효과 — 도메인 원칙 명문화

이번 사건을 계기로 사용자가 명시한 시스템 원칙을 **CLAUDE.md / PRD / Architecture / DB_SCHEMA 모두에 정식 등재**:

> **🔥 사이트 = DB 진실 일치 원칙 (CLAUDE.md §위생 #9, 2026-04-27 신설)**:
> "사용자가 거래소 공식 웹사이트에서 직접 보는 모든 데이터가 TRAVIS 의 DB / 카드 / AI 응답과 완전히 일치해야 함. M2+ 확장 시 거래소 사이트의 모든 데이터를 지원 지향."

### 1. **옵션 A (`!ticker@arr` 전환) 채택** — 사용자 결정

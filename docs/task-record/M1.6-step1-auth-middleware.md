## 📖 비전공자 친화 설명

**TRAVIS 에 "은행 지점급 3중 신원확인 잠금장치"를 처음 다는 단계입니다.**

이번 Step 1 전까지 TRAVIS 의 AI 호출 창구인 `/api/orchestrate` 는 **누구나 방문만 하면 호출 가능한 상태** 였습니다. 이건 곧 "누군가 지나가면서 내 앱을 몇 번 두드리기만 해도 Anthropic(AI 회사) 청구서가 제 이름으로 올라오는" 구조였습니다. Step 1 은 그 문을 닫는 작업입니다.

### 비유 — 은행 지점의 3중 신원확인

1. **정문 경비원 (middleware.ts)** — 손님이 들어올 때 먼저 보안카드(쿠키)를 확인. 카드가 없거나 가짜면 `401 Unauthorized` 로 문밖에 되돌려보냅니다. 카드가 유효한데 만료가 가까우면 새 카드(refresh 된 쿠키)로 갱신해서 쥐여줍니다.
2. **창구 직원 2차 확인 (route.ts POST 핸들러 맨 앞)** — 경비원이 실수로 놓친 경우를 대비해 창구에서 한 번 더 신분증을 확인. 같은 사람이 두 번 다른 사람으로 둔갑할 수 없게 하는 "defense-in-depth" 원칙.
3. **창구 두 종류 (browserClient / serverClient)** — Supabase 와 대화하는 창구가 두 개 있습니다. 브라우저(손님 지갑 안) 는 한 번 만든 창구를 **재사용** 하는 반면, 서버(지점 안) 는 **요청마다 새 창구** 를 엽니다. 이유는 "A 손님의 쿠키가 B 손님 요청에 섞이는 대형 사고" 를 원천 차단하기 위해. 기존 관리자 창구(`serviceRoleClient`, master 키) 와 더해 **3개 창구가 서로 다른 권한** 을 갖는 대칭 구조.

### 새로 생긴 화면

- **`/login`, `/signup`** — Next.js 의 Route Group 기법(`(auth)` 괄호 폴더) 으로 만들어 URL 에 `/auth/` 는 보이지 않으면서도 캔버스와 다른 "가운데 정렬된 카드" 레이아웃을 씁니다.
- **회원가입/로그인 폼** — 이메일 형식 검증 + 비밀번호 **최소 8자** 검증을 Zod 로 프론트에서 미리 걸고, 제출 중엔 버튼이 비활성화(이중 클릭 방어). 실패 시 영어 에러 메시지가 카드 안에 표시.
- **우상단 UserMenu** — 로그인된 이메일 + Log out 버튼이 캔버스 우상단 fixed 위치(좌상단 테마 토글과 대칭). 다른 탭에서 로그아웃하면 이 탭도 **즉시 반응** (`onAuthStateChange` 구독).

### 왜 Step 1 이 가장 중요한가

Step 2 부터의 모든 작업(`log_chat` / `log_behavior` 로그 테이블 / RLS 등) 은 **"이 요청이 누구의 것인가?"** 라는 질문에 답이 있어야 의미가 생깁니다. Step 1 이 없으면 뒤의 모든 사용자별 로그가 "누가 썼는지 모르는 로그" 가 되어 `[9-9]` 실사용 피드백 수집조차 불가능.

## 🧭 주요 의사결정

### 1. **C1 처리 "옵션 B" 채택** (code-reviewer 자문 후 사용자 확정)

- **기각된 옵션 A**: 지금 `OrchestrateFallbackReasonSchema` 에 `"unauthorized"` enum 을 추가하고 `messageForReason` switch + ChatInputBar 분기 전부 일괄 수정.
- **기각 이유**: Step 4 의 `fallbackReason` 세분화 (`parse_error` / `schema_drift` 분리) 가 이미 계획됨. 지금 `unauthorized` 만 먼저 추가하면 **Step 4 에서 같은 파일을 다시 건드리는 중복 작업**. CLAUDE.md "한 번에 하나의 작업" 원칙 위반.
- **옵션 B 선택**: ChatInputBar 의 `!res.ok` 블록에 `res.status === 401` 분기만 추가. body `.message` 를 토스트로 노출. Step 4 에서 enum 이 세분화되면 `setStatus("error", "unauthorized")` 의 두 번째 인자를 enum 상수로 깔끔히 전환.

### 2. **C1 blast radius 확장 최소화** (기존 한국어 영문화 범위 한정)

- ChatInputBar 의 `!res.ok` 블록 내부 한국어 2문장은 새 영어 401 메시지와 섞이면 UX 가 기형적으로 보여 같이 교체.
- **그러나 catch 블록 / placeholder / aria-label** 의 한국어는 같은 파일 내지만 블록 경계 밖이라 deferred-task `[3-15]` 로 이월 — C1 의 원래 책임(401 UX) 을 넘어 English-only 스위프로 확장되는 scope creep 차단. 사용자 "C1+C2+W1+W2 지금 / 나머지 이월" 결정 준수.

### 3. **사용자 env 설정과 Supabase 대시보드 설정 사용자 직접**

- `.env.local` 에 `NEXT_PUBLIC_SUPABASE_ANON_KEY` 는 secret 영역이므로 Claude 가 파일에 쓰지 않음 (사용자 직접 추가).
- Supabase Dashboard 의 "Confirm email OFF" 도 대시보드 영역이라 사용자 직접 설정. Step 1 **"즉시 로그인"** 원칙의 전제 조건.

### 4. **tsconfig include 확장을 Step 1 에 편입**

- `middleware.ts` 가 어디서도 import 되지 않아 type-check 누락 → 프로덕션에서 middleware 가 깨지는 경로가 열려있던 잠복 결함. 이번 Step 1 이 middleware.ts 를 신규 추가하는 Step 이므로 가장 자연스러운 정리 시점.
- 부수적으로 `components/**` 도 include 에 명시 추가. `vitest.setup.ts` 를 include anchor 로 삼아 jest-dom matcher 가 전파되도록.

### 5. **비밀번호 최소 길이 8자**

- Supabase 기본(6자) vs 12자 강화 중 **8자 권장** 채택. 트레이더 UX 와 기본 보안의 균형. M2+ MFA 도입 시 12자+ 로 자연스러운 승격 경로.

## 📖 비전공자 친화 설명

TRAVIS를 짓기 전에 **부지를 측량하고 기초 콘크리트를 까는 단계**입니다. 지금 만든 것은 전부 "건물 자체"가 아니라 **앞으로 건물을 올릴 때 지켜야 할 규칙**이에요. 사용자가 보는 화면도, 거래소 연결도, 데이터 창고도 이 단계에서는 존재하지 않습니다.

조금 풀면 이렇습니다. TRAVIS는 결국 두 개의 큰 앱(`apps/web` = 사용자가 보는 웹 화면, `apps/worker` = 24시간 돌아가며 거래소에서 데이터를 긁어오는 서버)과 여러 개의 공유 부품 창고(`packages/shared`, `packages/data-service`)로 구성될 예정입니다. 이렇게 여러 프로젝트를 한 저장소에 묶어 관리하는 방식을 **모노레포**라고 합니다. 그 울타리를 선언한 게 `pnpm-workspace.yaml`이고, 모든 프로젝트가 공통으로 쓸 도구(prettier, typescript)를 한 번만 설치하는 공용 공구함이 루트 `package.json`입니다. `tsconfig.base.json`은 "우리 가족 모두 이 문법 규칙을 따른다"는 가훈이에요 — 그 안의 `noUncheckedIndexedAccess`는 배열에서 값을 꺼낼 때 반드시 "없을 수도 있다"는 가정을 하게 강제해서, **CLAUDE.md의 "절대 crash하지 마라" 원칙을 타입 수준에서 의무화**합니다.

특히 이 단계에서 중요한 건 `.env.example`입니다. web 영역(공개 가능한 anon 키)과 worker 영역(절대 노출되면 안 되는 service_role 키)을 물리적으로 분리해 주석으로 표기해뒀어요. **이건 TRAVIS의 3개 데이터 경로 보안 모델의 첫 시각화**입니다 — AI는 Supabase anon 쪽만 보고, 워커만 service_role을 다룹니다. 이 경계를 흐리면 프로젝트의 안전이 무너지므로, 처음부터 시각적으로 갈라둔 것은 장기적으로 큰 이득입니다.

이 단계를 건너뛰었다면 어떤 고통이 있었을까요: ① 패키지마다 TypeScript 규칙이 제각각이어서 한쪽에서 통과한 코드가 다른 쪽에서 깨지고, ② Prettier 없이 작업하면 PR마다 스타일 싸움이 생기고, ③ `.env.example`이 없으면 새 컴퓨터/새 팀원이 "무슨 키가 필요한지" 모른 채 헤맵니다. 그래서 이 "부지 정리"를 안 한 채로 Step 2~6을 짓기 시작하면 3배 고생합니다.

## ⚠️ 다음 step에서 조심할 것

- **Step 3 (apps/web 구축)**: `tsconfig.base.json`의 `verbatimModuleSyntax: true` × shadcn/UI 템플릿이 충돌할 수 있음. 마찰 발생 시 → (A) apps/web tsconfig에서 `verbatimModuleSyntax: false`로 오버라이드 또는 (B) shadcn 산출물만 수동 수정. context7로 Next.js 16 + shadcn CLI 최신 동작을 먼저 확인 권장.
- **Step 3 (apps/web 구축)**: 루트엔 `prettier-plugin-tailwindcss`만 devDep으로 깔려있음 — `apps/web/.prettierrc`에서 `plugins: ["prettier-plugin-tailwindcss"]` + `tailwindStylesheet: "./app/globals.css"` **두 줄 모두** 추가해야 Tailwind v4에서 동작. 한 줄만 넣으면 v4는 경고.
- **Step 4 (apps/worker)**: `tsconfig.base.json`의 `lib: ["ES2022", "DOM", "DOM.Iterable"]`이 워커에도 상속되면 Node.js 환경에서 `window`/`document` 호출이 type-check를 통과해버림. 워커 tsconfig에서 `"lib": ["ES2022"]`로 좁혀 오버라이드 필수.
- **Step 5 (env 투입) 전까지**: `.env.*` 와일드카드는 이미 반영됐지만, 실제 `.env.local`/`.env` 파일 생성 시점에 `git status`로 다시 한 번 검증 필요 — "실제 파일 없이 통과"와 "실제 파일 있어도 통과"는 별개의 안전망.
- **일반**: code-reviewer W4 — `.claude/agents/` 전체가 gitignore되어 팀원 공유 불가. 현재는 solo 창업자라 문제 없지만 팀원 합류 시점에 의도 재확인 필요.
